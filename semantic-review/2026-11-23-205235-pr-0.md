# Three-workspace baseline closes two bypasses but still cannot prove its browser and type-policy boundaries

Task 1 establishes the three prescribed pnpm workspaces, builds both static Vite applications against `@covenant/core`, emits Core, and runs the LOC gate from both required command paths. The generated-path LOC bypass and missing `sideEffects` metadata are fixed, and the effective TypeScript configurations retain the required strict options. The exact verification command passes on Node 20.20.0 with pnpm 9.15.0, but its browser and explicit-`any` checks still accept prohibited production code. **Watch for:** **confirmed, high severity** browser safety is checked through a direct Node source import and uninspected bundles; **confirmed, medium severity** the explicit-`any` scan is a fixed file whitelist outside build and typecheck.

**Verdict**: NEEDS_CHANGES

## High-level view

The LOC scanner now excludes only the direct `src/generated/**` subtree and has a negative fixture for `src/internal/generated/**`. The Core manifest now declares `sideEffects: false`, matching the design.

The test confirms effective strict options for all three workspace typecheck configurations, and Core's build configuration is also strict. Its explicit-`any` AST check covers every current Task 1 TypeScript file, but manual enumeration makes every future production module invisible unless someone updates the list.

Both applications now import `@covenant/core`, so Vite consumes the package export. The boundary test still imports `../src/index.js` under Node, scans only `src/index.ts`, and never checks a browser module graph or output. Tree-shaking can hide a prohibited transitive root export while every prescribed command remains green.

## Browser-safe root proof stops at one source file

**Confirmed, high severity.** The test rejects forbidden strings only in `src/index.ts`, then imports that source entry under Vitest's Node environment (`packages/covenant-core/test/package-boundary.test.ts:126-142`; `packages/covenant-core/vitest.config.ts:3-6`). It does not resolve the built export in `packages/covenant-core/package.json:10-16`, inspect transitive modules, or scan either Vite output. Its application assertions check only dependency declarations and import text (`package-boundary.test.ts:144-150`).

A temporary-copy probe added an unlisted module exporting `NodeZ3Solver` and re-exported it through `export *`. The focused boundary test, `pnpm build`, and `pnpm typecheck` all passed. Core emitted the prohibited class, while Rollup removed it from both applications because they import only `COVENANT_CORE_VERSION`. The gate therefore misses a violation of ADR 0002 and `design.md:54-55,73-77,1095-1100`, even though the current artifacts contain no forbidden markers.

Add a Vite fixture that resolves the built package root and inspect its transitive graph and output. Scan the fixture and both final applications for `z3-solver`, `.wasm`, `NodeZ3Solver`, Node built-ins, and `SharedArrayBuffer`; a prohibited transitive export must fail even if application tree-shaking removes it.

## Explicit-any enforcement does not follow source growth

**Confirmed, medium severity.** `explicitAnyLocations` finds TypeScript `AnyKeyword` nodes, but the test applies it only to seven hard-coded files (`packages/covenant-core/test/package-boundary.test.ts:34-47,114-123`). Core build and root typecheck run only `check:loc` and `tsc` (`packages/covenant-core/package.json:18-24`; `package.json:9-14`), and strict TypeScript permits explicit `any`.

The temporary-copy probe put explicit `any` annotations in the new production module. The boundary test, build, and typecheck still passed. Requirement 1.1's strict flags are satisfied, but the design's source-wide no-explicit-`any` gate remains unenforced (`design.md:1095-1100`), and it will not protect requirement 1.2 when Task 2 adds the parser boundary (`requirements.md:17-19`).

Use deterministic recursive discovery for policy-covered TypeScript files, or an equivalent lint/compiler-API script. Invoke it from Core build and root typecheck so later task commands cannot bypass it.

## Previous LOC, strictness, and package-metadata findings are resolved

`isGenerated` now requires `generated` to be the first path segment below `src` (`packages/covenant-core/scripts/check-loc.mjs:11-20`), and the nested fixture proves `src/internal/generated/escape.ts` still counts (`packages/covenant-core/test/package-boundary.test.ts:153-177`). The scanner reports one production line, fails at 1,200, includes `src/tribunal-ui`, and runs from Core build and root typecheck. Requirements 16.3 and 16.7 are satisfied.

The test parses effective workspace options and checks `strict`, `noImplicitAny`, `strictNullChecks`, `noUncheckedIndexedAccess`, and `exactOptionalPropertyTypes` (`package-boundary.test.ts:25-31,84-112`). Independent `tsc --showConfig` checks confirmed those flags for Core typecheck, Core build, and both applications, satisfying requirement 1.1. `sideEffects: false` is present and asserted (`packages/covenant-core/package.json:6`; `package-boundary.test.ts:127-136`), matching `design.md:1003-1018`.

ADRs 0001 and 0003 are not implicated by this baseline. Requirement 16.4 currently has only a one-module production graph, so there is no cycle or domain-model dependency to violate. Requirement 16.1's feature exports and requirement 1.2's parser behavior become exercisable in later tasks; Task 1 provides the intended baseline root export and package consumption.
