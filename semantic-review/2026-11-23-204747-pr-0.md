# Three-workspace baseline builds, but its boundary proof has bypasses

Task 1 adds the Core package, two static Vite applications, a frozen pnpm graph, strict TypeScript inheritance, and a TypeScript-scanner LOC gate. The prescribed command passes on Node 20.20.0 with pnpm 9.15.0, and the current source contains no explicit `any`. The LOC gate has a directory bypass, while the browser and zero-`any` checks do not exercise the artifacts or effective policy they claim to prove. **Watch for:** **confirmed, high severity** LOC exclusion broader than `src/generated/**`; **confirmed, high severity** browser-safety verification that bypasses the package and bundles; **confirmed, medium severity** no enforceable explicit-`any` check; **confirmed, low severity** missing `sideEffects` metadata from the designed package boundary.

**Verdict**: NEEDS_CHANGES

## High-level view

The exact install, focused test, recursive build, and recursive typecheck complete successfully. The lockfile pins all direct and transitive versions, and all three effective TypeScript configurations currently retain the required strict flags.

The LOC scanner checks token-bearing physical lines and the threshold, but it excludes every subtree named `generated`. Production code outside the sole allowed `src/generated/` subtree can therefore evade the budget.

The boundary test imports source under Vitest's Node environment instead of resolving the built `@covenant/core` export through a browser bundler. Neither application imports Core, and the command never scans built artifacts, so successful Vite builds do not prove Core's browser boundary.

`noImplicitAny` permits explicit `any`. The required source scan is absent, the test checks inheritance text instead of each workspace's effective compiler settings, and the Core manifest omits the design's `sideEffects: false` declaration.

## The LOC exclusion accepts undeclared generated subtrees

**Confirmed, high severity.** `isCountedFile` excludes a file whenever any relative path segment equals `generated` (`packages/covenant-core/scripts/check-loc.mjs:11-20`). Requirement 16.3 and the design permit only `src/generated/**` (`.kiro/specs/01-covenant-core/requirements.md:341`; `.kiro/specs/01-covenant-core/design.md:99`). A review fixture containing 1,200 production lines at `src/internal/generated/escape.ts` reported `0/1199` and exited successfully. The checked-in test covers `src/generated/data.ts` but no disallowed nested generated directory (`packages/covenant-core/test/package-boundary.test.ts:90-109`).

Restrict the exception to a relative path whose first segment is exactly `generated`. Add a fixture proving `src/internal/generated/*.ts` still counts.

## Browser safety is tested through a Node source import

**Confirmed, high severity.** The test reads export-map strings, scans only `src/index.ts`, then imports `../src/index.js` directly (`packages/covenant-core/test/package-boundary.test.ts:74-88`). This bypasses package resolution and `dist/index.js`, and it runs in the Node environment (`packages/covenant-core/vitest.config.ts:3-6`). A transitive root export can import a Node-only module while both the regex and Node import still pass.

The browser entries import only React (`app-1-spec-inquisitor/src/main.tsx:1-2`; `app-2-clause-exorcist/src/main.tsx:1-2`), so Core never enters either Vite graph. The exact command performs no post-build artifact check even though requirement 16.6 requires browser artifacts to prove Z3 WASM and Node adapter code are absent (`.kiro/specs/01-covenant-core/requirements.md:347`). The current artifacts contain no `z3-solver`, `.wasm`, `NodeZ3Solver`, or `SharedArrayBuffer`, but they cannot validate a package they do not bundle.

Add a browser fixture that consumes `@covenant/core` through Vite, then inspect its graph and output for forbidden dependencies and symbols. A built-package import should replace the direct source import as the package-boundary assertion.

## Strict mode does not enforce the zero-any policy

**Confirmed, medium severity.** The current source has no explicit `any`, and `tsc --showConfig` confirms all required flags today. The test checks only root JSON values and child `extends` strings (`packages/covenant-core/test/package-boundary.test.ts:59-72`), so a child can override a flag. TypeScript also accepts explicit `any` under `strict` and `noImplicitAny`.

The design requires strict typechecking plus an explicit-`any` source scan (`.kiro/specs/01-covenant-core/design.md:1095-1100`), but neither the boundary test nor command-path scripts provide that scan (`package.json:9-14`; `packages/covenant-core/package.json:17-23`). Add an AST or lint gate and assert effective options, such as parsed `tsc --showConfig` output.

## Core package metadata omits the designed tree-shaking contract

**Confirmed, low severity.** The designed package boundary includes `"sideEffects": false` (`.kiro/specs/01-covenant-core/design.md:1001-1018`), while the Core manifest omits it (`packages/covenant-core/package.json:5-16`). Add the metadata and test it. If later Tribunal CSS requires side effects, narrow the field to the intended CSS exception.
