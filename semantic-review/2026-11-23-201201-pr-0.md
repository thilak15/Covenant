# Haunted Tribunal specifications align the shared evidence UI but leave key contracts unresolved

The feature-02 requirements define a strong shared evidence experience over feature 01 and preserve verdict, repair, and telemetry boundaries. All 99 numbered acceptance criteria match a required Kiro EARS sentence form. Blocking gaps remain in the feature artifacts, normative visual tokens, representable UI states, and legal fixture semantics. **Watch for:** **confirmed** missing lowercase spec artifacts and token values; **confirmed** props that cannot carry required diagnostics and error states; **confirmed** source-to-AST drift in `LIAB-01` and the background-IP relationship; **likely** SLA repairs outside the fixture’s formal vocabulary.

**Verdict**: NEEDS_CHANGES

## High-level view

The requirements keep `PASS`, `FAIL`, and `UNKNOWN` distinct, leave proven failures independent from repair availability, separate OpenPBTStats from Verification Telemetry, and prohibit browser Z3 and live property suites. These choices align with ADRs 0002 and 0003.

**Confirmed:** The feature directory contains `requirements.md` and uppercase `DESIGN.md`, but the convention also requires lowercase `design.md` and `tasks.md`. Requirement 12.3 points at the missing lowercase file even though uppercase `DESIGN.md` contains the fixtures.

**Confirmed:** The visual direction is specific to COVENANT, but the supposedly normative design system contains aliases rather than primitive token values. The promised font fallback stacks and exact color, type, spacing, shape, shadow, and component values are absent.

**Confirmed:** The public React contracts cover the happy path but cannot carry all required state. Parser diagnostics, active filtering, missing-witness evidence, invalid PBT snapshots, and clipboard failure lack representable inputs or outcomes.

**Confirmed:** The liability fixture drops a source activation condition, and the freelance fixture makes background-IP retention independent from transfer of “all delivered work.” **Likely:** The SLA pair descriptions require credit amount and temporal concepts absent from the declared fixture.

## Feature artifacts and case-sensitive references

**Confirmed concern.** The convention requires `requirements.md` and lowercase `design.md` for every feature, one `tasks.md`, and a separate uppercase UI-system `DESIGN.md` (`.kiro/steering/issue-tracker.md:9-14`). The reviewed directory contains only `requirements.md` and `DESIGN.md`. Requirement 12.3 names lowercase `design.md` (`.kiro/specs/02-haunted-tribunal-ui/requirements.md:219`), while fixtures begin in uppercase `DESIGN.md` (`.kiro/specs/02-haunted-tribunal-ui/DESIGN.md:314-316`). This reference fails on a case-sensitive checkout.

Add lowercase `design.md` for architecture, data flow, errors, and testing, plus `tasks.md`. Keep visual tokens in uppercase `DESIGN.md`. Move fixture architecture to lowercase `design.md` or correct requirement 12.3 to the exact owner.

## Normative visual system has no normative values

**Confirmed concern.** Requirement 2.1 demands exact color, typography, spacing, shape, and component tokens, while requirements 3.1-3.4 demand defined fallback stacks (`requirements.md:33,53-59`). Uppercase `DESIGN.md` calls itself normative (`DESIGN.md:12`) and says CSS maps “every frontmatter token” (`DESIGN.md:171-186`), but it has no token frontmatter. The aliases reference undefined primitives, and `DESIGN.md:189-191` supplies no fallback stacks, type scale, spacing, radii, borders, shadows, or component dimensions.

Add exact primitives and semantic aliases to uppercase `DESIGN.md`, including font stacks and forced-color mappings. Record tested foreground/background pairs so WCAG 2.2 AA at `requirements.md:45` is measurable.

## Inspector filtering and diagnostics have no data path

**Confirmed concern.** The Lantern Bar must filter findings (`requirements.md:75`), the inspector must display source-located diagnostics (`requirements.md:89`), and the edge table requires parser-rejection and empty-filter recovery (`DESIGN.md:301-305`). `SplitScrollInspectorProps` has neither the active Inquisitor nor diagnostics (`DESIGN.md:92-101`). Core stores diagnostics on parse and validation results, not on `CovenantDocument` or `VerificationReport` (`.kiro/specs/01-covenant-core/design.md:815-843`), so the inspector cannot derive them.

Add an active-filter prop and a discriminated source state carrying parse/validation diagnostics. Keep diagnostics separate from `VerificationReport` to preserve feature 01’s boundary.

## Evidence and recovery states conflict with their props

**Confirmed concern.** Requirement 6.5 describes a finding without a valid witness (`requirements.md:117`; `DESIGN.md:304`), but `PhantomWitnessStandProps` requires one (`DESIGN.md:103-106`). Feature 01 requires `ConsistencyEvidence.witness` and maps failed replay to `UNKNOWN`, whose verdict contains no findings (`.kiro/specs/01-covenant-core/design.md:616,646-650,726-744`). The feature-02 state conflicts with the upstream model.

**Confirmed concern.** `VerificationDrawerProps.pbt` accepts only a valid snapshot despite the invalid-snapshot state (`DESIGN.md:136-141,310`). **Confirmed concern.** `onCopy` returns `void`, so the component cannot observe denial and provide the fallback at `DESIGN.md:312`.

Render missing witness as a verdict-level `UNKNOWN/INVALID_EVIDENCE`. Add discriminated valid/error PBT input and controlled or result-returning clipboard state.

## Root export and CSS loading are unspecified

**Confirmed concern.** Applications must import Tribunal components from the package root (`requirements.md:19`), but feature 02 only identifies `src/tribunal-ui/index.ts` (`DESIGN.md:55-64`). Feature 01’s root list omits React UI (`.kiro/specs/01-covenant-core/design.md:1021-1027`). Feature 01 also declares `sideEffects: false` (`design.md:1005-1018`), while feature 02 depends on `tribunal.css` without specifying an export, consumer import, or side-effect exception.

Specify the browser-safe root re-export and one CSS-loading contract. Mark CSS as a package side effect if components import it, or export a CSS subpath and require both applications to import it. Preserve the Node-only subpath boundary.

## Liability source trigger is lost

**Confirmed concern.** `LIAB-01` applies “WHEN Supplier liability arises” (`DESIGN.md:570-573`), but its Rule has `activation: TRUE` (`DESIGN.md:597-603`). The formal cap therefore applies to every modeled supplier payment, broader than the authoritative source.

Declare `liabilityArises` and use it in activation or `RuleScope.context`; include `liabilityArises=true` in the expected witness. The intended `LIAB-01`/`LIAB-02` contradiction remains jointly applicable.

## Background IP is disconnected from “all delivered work”

**Confirmed concern.** `IP-01` transfers “all delivered work,” while `IP-03` retains background IP contained in delivered work (`DESIGN.md:638-642`). Their AST Rules use mutually exclusive action values and unrelated Boolean consequences (`DESIGN.md:654-688`). Under ADR 0001, they cannot interact, so the model cannot test whether “all” sweeps in background IP.

If `IP-03` is only a preserved unrelated Rule, narrow `IP-01` source text to project-specific work excluding background IP. Otherwise model both Rules over compatible applicability and opposite conditions on the same ownership subject.

## SLA repairs outrun the declared theory

**Likely concern.** The fixture declares only Boolean credit and cure-start states, outage cause, notice, and uptime (`DESIGN.md:724-732`). Its repairs introduce a reduced credit, a paused cure clock, tolled elapsed days, and a post-event deadline (`DESIGN.md:792-796`). Those require amount or temporal state absent from the fixture. Feature 01 forbids approximating unsupported theory (`.kiro/specs/01-covenant-core/design.md:1117-1124`), and the prose does not establish distinct normalized post-patch models.

Provide exact guarded edits and post-patch ASTs in the supported Boolean/enum/exact-bound model, adding explicit finite-state or exact numeric declarations where needed. Each patch must remain inside its Repair Core and produce a distinct semantic fingerprint.

## Keyboard and test contracts omit required detail

**Confirmed concern.** The separator specifies `aria-valuenow` but no accessible name or `aria-valuemin`/`aria-valuemax` despite bounded resizing (`requirements.md:101`; `DESIGN.md:211-213`). The drawer requirement mandates Escape and focus preservation (`requirements.md:175`), but `DESIGN.md:248-254` does not define when Escape closes it or where focus returns.

**Confirmed concern.** Requirement 16.3 requires shared tests for loading, empty, error, and overlong states (`requirements.md:295`). The shared test list omits them (`DESIGN.md:830-845`); overlong content appears only in the visual matrix.

Specify the custom-control semantics and add the omitted behavioral tests. Keep visual regression for layout rather than using it as an interaction substitute.

## Strengths to preserve

All 99 acceptance criteria use one of the four exact EARS forms required by `.kiro/steering/issue-tracker.md:10-12`, and every requirement has a user story and numbered criteria. Explicit widths, motion durations, state labels, bundle strings, and offline behavior make many criteria directly testable.

The formal boundaries match ADRs 0001-0003. `DESIGN.md:16-22,161-169` preserves source/evidence linkage, immutable report state, verdict/repair independence, and browser-only solving. Exact witness formatting avoids `Number()` (`DESIGN.md:215-229`), current numeric fixtures use reduced rationals, and the stated Consistency findings all have jointly applicable Rules before incompatible consequences.

Accessibility and static-runtime coverage are strong. The specs pair state color with text and icons, preserve visible focus and DOM reading order, distinguish polite status from assertive action failure, define reduced-motion alternatives, block outbound network use, and inspect bundles for Node/Z3 leakage (`requirements.md:269-301`; `DESIGN.md:270-312,861-871`).
